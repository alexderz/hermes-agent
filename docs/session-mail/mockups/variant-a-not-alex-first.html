What to look at
  1. First wrapped line: 📡 Not Alex · reply requested ·. Glance words survive any title length.
  2. Every user row is clamped to four lines and fades from about halfway. On a phone the expand chevron ⌄ under the row lifts the clamp (a tap on the row itself does not). On desktop a click on the row opens the edit composer, which shows the whole text: leave with Esc, because sending an edit rewinds the turn. So the glance words always show, and the authority line, footer and closing line show once expanded. Text is plain apart from inline code and fences. No delivery ticks (that was Hermes Mobile).

silent a bare [SILENT] answer is never posted here (Trial R4)
Posted only to a private chat (LLD TB-5): an owner DM (a user listed in plugins.entries.intercom.settings.owner_user_ids), or a chat listed in plugins.entries.intercom.settings.echo_chats, as this topic is. Values are "<platform>:<id>", for example "telegram:<chat id>". An unlisted group or topic is shared: the mail is still delivered, but nothing is posted, so only the answer appears (see “States”), the target's model gets the shared-chat line, and a reply to a shared-chat sender carries only an explicit [REPLY] block.

Only header line 1 and the body are posted, escaped for the chat's renderer so links and mentions are inert; a platform with no escaper gets no echo. The post comes from the target's own turn: as a queued or started turn begins, or, for a steer, just before the model's next request reads it. For a steered message, the post is made just before the model's next request reads it, whether that step is a tool call or the answer (LLD B6). If those hooks do not fire for messaging chats (HLD O21), the echo is dropped for v1 and only the answer appears. For C, both card lines are posted.
