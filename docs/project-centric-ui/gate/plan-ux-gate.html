We write no app code. You review and post two issues:
Issue 1: tapping a project opens this screen (settings move behind Edit). The main chat is on top; /new in it compacts the chat like Bot Chat does; if a run elsewhere holds the chat, show "Working in another window" and offer Send when it finishes instead of only "New conversation".
Issue 2: the stray "hermes" group in History becomes "Home"; new project chats start in the project's primary folder, not its first one.

Works today with no app change: once owner chats run through the dashboard ("Owner-chat runs" below), opening a working main chat on the phone joins the live turn, so you can queue, steer or stop it. That's the fix for the SESSION_NOT_OWNED error you hit. The Trial proved this with a stand-in client (18/18 checks), not yet with the real app.

4 · What gets built behind it

Main-chat fieldOne optional field per project (owner_session_id), returned by the calls the phone app already makes. A small Hermes patch on the fork, offered upstream through an issue draft you post.
Projects tabA plugin inside the fork, so no changes to core dashboard code and no web rebuild. It only reads the existing project list.
SeedingSet once: the five "— Orchestrator" chats plus Model Master become the main chats. An undo file is written first.
Owner-chat runsA new hermes command (in the same plugin) runs owner-chat turns through the dashboard instead of chat -q --oneshot. Cost: a dashboard restart kills a running owner turn, so planned restarts wait for it or ask you.
DeployOne announced dashboard restart (cuts the phone off briefly).
Not in this sliceA server-side /new guard, a "make main chat" button, a main chat for Home, the installable web app (PWA), our own build of the app, the move to v0.23.0, a "Live" badge on the Projects pages.
